# Börü V3.0 — V2.3–V3.0 toplu geliştirme paketi

Bu kilometre taşları tek paket halinde sunulur. `python main.py` veya
`python main_v3000.py` V3.0'ı açar. V2.3–V2.9 girişleri aynı görev güvenilirliği
paketini kullanır; V3.0 buna terminal girişini ekler.

| Madde | Uygulanan davranış |
| --- | --- |
| V2.3 | Her checkpoint yazımında önceki doğrulanmış kaydın atomik yedeği; ilk kayıt da yedeklenir. |
| V2.4 | Zaman aşımı, erişim, doğrulama, kaynak değişimi ve öneri hatalarını ayıran görev raporları. |
| V2.5 | `task yeniden dene: TASK-1`; task başına en fazla 3 başlatma. Sayaç yeniden başlatma ve sıfırlamada korunur. Her deneme yeni öneri/onay gerektirir. |
| V2.6 | Proje başına işletim sistemi kilidi ve checkpoint dış değişim kontrolü. İkinci V3 oturumu aynı proje kilidini alamaz. Süreç kapanınca kilit otomatik bırakılır. |
| V2.7 | Eksik/bozuk checkpoint nedeniyle görev yazımlarını durdurma; öneri ve açık onayla yedekten kurtarma; eski ana dosyayı ayrı dosyada koruma. Kesilen running görev pending olur. |
| V2.8 | Kaynak hash'i ve 7 günlük plan geçerliliğinin başlatma ve onay öncesi kontrolü. Eski planda zaman kaydı yoksa yeniden planlama gerekir. |
| V2.9 | Değiştirilen planları otomatik arşivleme; tamamlanmış planı açık komutla arşivleme; en fazla 50 arşiv. Arşiv dolunca kayıt silinmez, kullanıcıya bildirilir. |
| V3.0 | `terminal:` girişiyle canonical unittest/pytest/ruff check/mypy komutları; gerçek çıkış kodu, süre ve çıktı; Docker ortam durumu. |

## Komutlar

Komutları ayrı mesajlar halinde gönderin:

```text
checkpoint durumu
görev günlüğü
plan sağlığı
görev arşivi
task yeniden dene: TASK-1
planı arşivle
checkpoint geri yükle
checkpoint geri yüklemeyi onayla
terminal durumu
terminal: python -m unittest tests/test_v3000.py
terminal: pytest tests
terminal: ruff check boru/tasks
terminal: mypy boru
```

`task yeniden dene` yalnızca failed task için kullanılabilir. `planı arşivle`
yalnızca tüm taskları tamamlanmış planı aktif durumdan kaldırır. Yeni plan
oluşturmak eski planı arşivler. Kurtarma önerisinde `iptal` desteği vardır;
salt `onayla` yeterli değildir. Onaydan önce ana dosya veya yedek değişmişse
geri yükleme reddedilir. Onaylar diske kaydedilmez.

## Veri ve kurtarma

Yeni kayıtlar `boru.task-checkpoint/v3` zarfında V2 plan/günlük/hash içeriği ile
oluşturma zamanı ve deneme sayaçlarını saklar. V1/V2 içerik doğrulanır ve eski
biçimi yedeklenerek V3'e taşınır. Bilinmeyen kök/iç alanlar veya gelecek sürümler
veri kaybına yol açmamak için reddedilir. V2.2'den kalan etkin plan görüntülenir;
zaman kaydı olmadığından çalıştırmak için yeniden planlanmalıdır.

Varsayılan dosyalar:

- `data/task_checkpoint.json`: etkin kayıt.
- `data/task_checkpoint.json.backup`: önceki geçerli kayıt.
- `data/task_checkpoint.json.damaged-<id>`: geri yükleme öncesi ana kaydın kopyası.
- `data/task_checkpoint_archive/<id>.json`: arşivlenen planlar.
- `data/task_project.lock`: işletim sistemi kilidi için sabit dosya. Dosyanın
  varlığı kilidin aktif olduğunu göstermez; dosyayı silmek gerekmez.

Geri yükleme yalnızca görev durumunu geri getirir; kaynak kodu geri almaz.
Eski yedekle güncel kaynak uyuşmazsa drift denetimi çalıştırmayı durdurur.
Kurtarma testi için gerçek checkpoint'i kasıtlı bozmak yerine geçici dizinlerdeki
otomatik testleri kullanın. Arşiv ve kurtarma kopyaları otomatik silinmez.

## Terminal sınırları

Terminal bu sürümde izinli Python test/statik analiz araçlarını çalıştırır.
Genel PowerShell/bash, `python -c`, paket kurulumu, pipe, yönlendirme ve ek
komut bayrakları desteklenmez. Python modülü/imaj içindeki araç eksikse hata
raporlanır, bağımlılık otomatik kurulmaz. Host üzerinde komut çalıştırma fallback'i
yoktur. Docker motoru ve `boru-sandbox:1.0` imajı gereklidir.

Mevcut sandbox sınırları korunur: salt-okunur proje kopyası, kapalı ağ,
120 sn, 1 MB çıktı, 1 CPU, 512 MB RAM, 64 PID. Test bulunamaması başarı sayılmaz.
