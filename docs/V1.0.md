# Börü V1.0 kullanım ve doğrulama

## Başlatma

Proje kökünde `python main.py` çalıştırın. Başlangıçta **Börü V1.0** yazmalıdır.
V0.27, V0.28 ve V0.29 ara girişleri sırasıyla `main_v270.py`, `main_v280.py`,
`main_v290.py` dosyalarıdır. Önceki giriş dosyaları eski davranışı korur.

Normal sohbet için önceki Ollama model ayarları kullanılır. Yeni kontrol komutları,
değerlendirme ve basit VALUE atama düzenlemeleri sohbet modeline bırakılmaz.
Daha karmaşık iyileştirme önerileri mevcut Architect/Coding modelini kullanır.

## V0.27 — Sandbox

Docker Desktop'ın Linux container motorunu başlatın. İlk kurulumda PowerShell'de:

```powershell
docker build -t boru-sandbox:1.0 -f sandbox/Dockerfile sandbox
python main.py
```

Farklı bir **güvenilir ve önceden hazırlanmış** imaj için `BORU_SANDBOX_IMAGE`
ortam değişkenini kullanın. Çalıştırma sırasında imaj indirilmez veya paket kurulmaz.
Dockerfile Python 3.13, git, Tk ve önceki uygulama/test bağımlılıklarını içerir.
Başka proje bağımlılıkları gerekiyorsa imajı önceden hazırlayın.

Börü sohbetine, her komutu ayrı mesaj olarak gönderin:

```text
sandbox durumu
```

```text
sandbox test: tests/test_v260.py
```

V0.27 ve sonrasında Test Agent, unittest/pytest/ruff/mypy ve otomatik düzeltme
testleri Docker üzerinden çalışır. Git ve API/SQLite araçları kendi mevcut
politikalarını kullanır; bu sürüm tüm uygulamayı bir sandbox içine taşımaz.

Container ağı kapalıdır, yetenekleri kaldırılmıştır, root olmayan kullanıcıyla
çalışır. Kaynakların geçici kopyası salt-okunur bağlanır. Ana proje klasörü,
Docker socket'i ve host ortam değişkenleri container'a aktarılmaz.
CPU 1, RAM/swap 512 MB, süreç 64, komut süresi 120 saniye, çıktı 1 MB ile sınırlıdır.
Geçici yazma alanı `/tmp` altında 64 MB'dır. Timeout sonunda container temizlenir.
Docker hazır değilse komut host üzerinde çalıştırılmaz.

Kaynak kopyası en fazla 2.000 metin dosyası / 16 MB içerir. `.git`, gizli yollar,
bağlantılar, `data`, `ai_hafiza`, derleme çıktıları ve bilinen anahtar dosyaları
aktarılmaz. Test fixture'larını `tests/fixtures` altında tutun. Kaynak metinlerine
gömülü tüm sırların otomatik ayıklanacağı garanti edilmez.
Workspace'e yazmayı veya dış servisi gerektiren testler bu profilde başarısız olabilir.

Docker sınırlarının referansı: [docker container run](https://docs.docker.com/reference/cli/docker/container/run/).

## V0.28 — Kanıta dayalı değerlendirme

```text
kendini değerlendir: boru/database_tools/service.py
```

```text
değerlendirme durumu
```

1–8 kaynak dosyası incelenir. Test keşfi, gerçek test çıkışı, statik Security ve
Code Review sonuçları ayrı kanıtlardır. Pozitif test sayısı olmayan veya atlanmış
test içeren sonuçlar tam başarı sayılmaz. Çalıştırılamayan test ile başarısız test
ayrılır. Kaynaklar ve kullanılan testlerin SHA-256 değerleri değişirse rapor
güncel kabul edilmez. Son rapor uygulama oturumunda tutulur.

Coding/Orchestrator sonrası kontroller de bu değerlendirmeyi kullanır.
Başarılı testler yalnızca kapsadıkları davranışı kanıtlar; iş gereksinimlerinin
tamamının karşılandığı, CVE veya canlı yetkilendirme güvenliği sonucu çıkarılmaz.

## V0.29 — Kontrollü iyileştirme

```text
iyileştir: boru/modul.py | boru/modul.py içinde somut sorunu yalnızca bu dosyada düzelt
```

Başlangıç değerlendirmesi ve diff görüntülenir. Tek öneri üretilir; arka planda
sonsuz düzeltme döngüsü veya çalışan uygulamayı yeniden yükleme yapılmaz.
Yalnızca belirtilen mevcut dosyalar düzenlenebilir. Yeni dosya gerekiyorsa önce
normal dosya oluşturma/Coding akışını kullanın.

```text
iyileştirmeyi onayla
```

Onaydan sonra öneri geçici kaynak kopyasında uygulanır. Bu kopyadaki testler
sandbox'ta çalıştırılır, statik kurallar taranır. Tüm kontroller geçerse asıl
dosyalar mevcut hash kontrollü transaction ile değiştirilir. Test yoksa, Docker
çalışmıyorsa veya bulgu varsa asıl değişiklik uygulanmaz. Proje kaynakları onay
ve doğrulama arasında değişmişse yeniden öneri hazırlamak gerekir.

V0.29 kalite kapısı yalnızca `iyileştir:` akışındadır; normal `kodla:` akışı
önce uygulayıp ardından raporlamaya devam eder.

Son başarılı iyileştirme bu oturumda geri alınabilir:

```text
iyileştirmeyi geri al
```

```text
iyileştirme geri almayı onayla
```

Geri alma hedefi sonradan dışarıdan değişmişse üzerine yazılmaz. Yeni başarılı
iyileştirme önceki geri alma kaydının yerini alır. Yeniden başlatma bu kaydı siler;
uzun süreli sürüm geçmişi için Git kullanın. `iptal` bekleyen öneriyi/geri almayı iptal eder.

## Baştan sona manuel test

Test dosyasını **Börü sohbetinde** oluşturun (girintileri koruyun):

```text
dosya oluştur: release_manual_test.py
İçerik:
import unittest

VALUE = 1

class ValueTests(unittest.TestCase):
    def test_value(self):
        self.assertEqual(VALUE, 2)
```

Ardından ayrı mesajlarda:

1. `onayla`
2. `kendini değerlendir: release_manual_test.py` → başarısız test beklenir.
3. `iyileştir: release_manual_test.py | release_manual_test.py içinde VALUE değerini yalnızca bu dosyada 2 yap`
4. `onayla` → özel iyileştirme onayı istenmeli, değişiklik yapılmamalı.
5. `iyileştirmeyi onayla` → kopyada test geçmeli, VALUE=2 uygulanmalı.
6. `kendini değerlendir: release_manual_test.py` → GEÇTİ.
7. `iyileştirmeyi geri al`
8. `iyileştirme geri almayı onayla` → VALUE=1 geri gelmeli.

Başarısız öneri testi için aynı hedefte VALUE=3 isteyin: onay verilse bile
`assertEqual(VALUE, 2)` geçmeyeceğinden asıl dosya değişmemeli.

## Otomatik doğrulama

```powershell
python -B -m unittest discover -s tests
$env:BORU_RUN_DOCKER_TESTS="1"
python -B -m unittest tests.test_v270.LiveSandboxTests tests.test_v1000.LiveReleaseWorkflowTests -v
```

İlk komut host üzerinde geliştirme regresyon testlerini çalıştırır; canlı Docker
testleri ortam değişkeni verilmezse atlanır. İkinci komut gerçek container'da
ağ/yazma/ortam sınırlarını ve geçici projede onay, doğrulama, uygulama, geri alma
akışını sınar. LLM yerine deterministik test modeli kullanıldığı için gerçek
modelin tüm görevlerde doğruluğunu veya gecikmesini ölçmez.

V1.0 bu çekirdeğin entegrasyon sürümüdür. Geniş yol haritasındaki web araştırması,
PostgreSQL/MySQL, çoklu proje, gelişmiş kod indeksi ve bağımsız güvenlik denetimi
bu sürümün tamamlanmış özellikleri arasında değildir.
