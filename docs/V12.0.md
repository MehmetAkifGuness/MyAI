# Börü V12.0 — araştırma, onarım ve ölçüm paketi

## Kullanım

Uygulamayı `python main.py` ile yeniden başlatın. GitHub veya Git gerekli değildir.
Yerel projenin kökünü seçmek için sohbet içinde komutları ayrı mesajlar olarak gönderin:

```text
repo seç: .
repo zeka durumu
repo akıllı analiz: boru/benchmark/coordinator.py içindeki durum komutunu açıkla
repo akıllı geliştir: boru/benchmark/coordinator.py içinde "benchmark durum" yazımı "benchmark durumu" ile aynı çalışmalı; tests/test_v7000.py ile doğrula
```

Araştırma yetersizse soru veya açık hata döner; kod önerisi varsa diff gösterilir.
Yazma için mevcut `kod değişikliğini onayla` komutu kullanılır. `iptal` bekleyen öneriyi kapatır.

## Birlikte çalışan bileşenler

- Araştırmacı en fazla dört model adımında kaynak okuyabilir, geliştirme sırasında bir kez
  sandbox test kanıtı isteyebilir ve teşhis/öneri verebilir. Salt analiz komutu test çalıştırmaz.
- Adaylar gerçek arama eşleşmeleri, import/çağrı ve ters bağımlılık ilişkilerinden gelir.
  Python dinamik çağrıları tam çözümlenmez; liste eksiksiz çağrı grafiği iddiası taşımaz.
- Kaynak pencereleri 160 satır/6000 karakter, toplam 12 pencere/24000 karakter ile sınırlıdır.
  Satır alıntıları gerçekten okunan içerikte doğrulanır. Bu kontrol, teşhisin anlam bakımından
  doğru olduğunu tek başına kanıtlamaz; test ve diff incelemesi gereklidir.
- Düzenleme ve test kapsamı ayrıdır. Belirtilen kaynak kapsamı genişletilemez; mevcut
  testler teşhis akışında değiştirilemez. Yeni modül/test üretimi bu araştırma akışında yoktur;
  önceki Coding komutları kullanılabilir.
- Çoklu dosya/onarım işleri yapılandırılmış yedek modele yönlendirilir. `BORU_MODEL` ve
  `BORU_FALLBACK_MODEL` mevcut ayarları kullanılır. Yeni model indirilmez; model kalitesi
  veya donanım kapasitesi yükseltilmiş sayılmaz. Yedek yoksa ana model kullanılır.
- Başarısız aday ve test çıktısı sonraki onarıma aktarılır. En fazla iki yeni onarım önerisi
  hazırlanır, her biri yeniden onay ister. Aynı başarısız yama tekrarına izin verilmez.
- Benchmark onarımında değişmeyen bağımlılıklar ve önceki aday değişiklikleri korunur;
  yalnızca son model yanıtındaki dosyalardan oluşan eksik bağlam kullanılmaz.
- Araştırmada okunan dosyaların SHA-256 değeri onayda kontrol edilir; seçilen testler geçici
  kopya doğrulamasına eklenir. Kaynak driftinde ana proje değiştirilmez.
- Deneyim kaydı yalnızca başarılı, güncel test/doğrulama raporundan oluşur. Proje başına
  en fazla 100 kayıt; dosya yolları, SHA-256 ve kullanılan model rolü saklanır. Ham sohbet,
  kaynak, gizli anahtar veya model talimatı saklanmaz. Aynı projede değişmemiş kaynaklarla
  ilgili en fazla üç kayıt araştırmaya verilir. Bu, model eğitimi/fine-tuning değildir.

## Ölçüm

```text
benchmark repo görevleri
benchmark çalıştır: qwen2.5-coder:7b | yedek=qwen3.5:9b | paket=repo | limit=5
benchmark durumu
```

CLI eşdeğeri:

```powershell
python -B -m boru.benchmark --model qwen2.5-coder:7b --fallback-model qwen3.5:9b --suite repo --limit 5
```

Repo paketi; komut yönlendirme, iç içe önbellek kopyalama, sayfalama, stok işlemi ve ayar
ayrıştırma için iç içe dizinli bağımsız Python fixture'ları içerir. Gizli kabul testleri
model girdisine verilmez. Temel 30 görevlik paket korunur. Rapor ilk deneme başarısını,
onarım/yedek model sonrası başarıyı ve süreyi ayrı gösterir. Beş sentetik görev, gerçek
GitHub projelerinde genel başarı oranı değildir; gerçek depo issue/patch veri kümesi
bu pakette eklenmemiştir.

Canlı model testi (isteğe bağlı; Linux Docker motoru ve kurulu Ollama modelleri gerekir):

```powershell
$env:BORU_LIVE_V12="1"
python -B -m unittest tests.test_v12000_live
```

### İlk canlı ölçüm

`data/benchmarks/v12-6636a45288694ec49f160863a8b36c09.json` raporunda
qwen2.5-coder:7b + qwen3.5:9b çifti 5 görevin 1'ini geçti (%20), 1 görev
başarısız oldu ve 3 görevde beklenmeyen netleştirme istendi. Toplam süre 616,425 saniye.
Bu ölçüm benchmark onarım bağlamı düzeltmesinden **öncedir**; düzeltilmiş sürüm için
yeni bir beş-görev ölçümü yapılmadan başarı artışı iddia edilemez. Sonuç model kalitesi
ve görev çözme güvenilirliğinin hâlâ geliştirilmesi gerektiğini gösterir.

Son kaynak araştırması canlı Ollama ile geçti: toplama/çıkarma fixture'ında kaynak
seçimi ve satır kanıtı doğrulandı, dosya değiştirilmedi. Süre 151,405 saniye; bir
tekrarlanan okuma ve bir model timeout sonrasında üçüncü adımda sonuç alındı.
Bu tek örnek hız veya genel görev başarısı garantisi değildir. Bu koşuda model test
eylemini seçmedi; Docker çalıştırma kanıtı ayrı benchmark koşusundandır.
